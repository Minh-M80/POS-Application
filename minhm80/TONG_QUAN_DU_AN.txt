================================================================================
      TỔNG QUAN DỰ ÁN: POS APPLICATION (POINT OF SALE SYSTEM)
================================================================================

Tên dự án   : minhm80 - POS Application Backend
Công nghệ   : Java 21 + Spring Boot 3.5.9
Database    : MySQL 8.0
Cache       : Redis 7
Port mặc định: 5000
Swagger UI  : http://localhost:5000/swagger-ui/index.html

================================================================================
I. Ý TƯỞNG DỰ ÁN
================================================================================

POS (Point of Sale) là hệ thống quản lý bán hàng tại điểm bán dành cho các
chuỗi cửa hàng (chain store). Hệ thống cho phép:

  1. Một tổ chức (Store) có thể có nhiều chi nhánh (Branch)
  2. Mỗi Branch có quản lý (Branch Manager) và thu ngân (Cashier)
  3. Thu ngân tạo đơn hàng (Order) và quản lý ca làm việc (Shift)
  4. Hệ thống tự động tổng hợp báo cáo ca (Shift Report) gồm doanh thu, hoàn
     tiền, các phương thức thanh toán, sản phẩm bán chạy...

Ví dụ thực tế: Chuỗi cà phê có 1 Store (công ty) → nhiều Branch (quán) →
mỗi quán có nhân viên, thu ngân → thu ngân bán hàng, kết ca sinh báo cáo.

IV. MÔ HÌNH DỮ LIỆU (DATABASE SCHEMA)
================================================================================

  [Store] ──────── 1:1 ──────── [User] (storeAdmin)
     |
     ├── 1:N ──── [Branch] ──── 1:1 ──── [User] (manager)
     |               |
     |               └── 1:N ──── [ShiftReport] (cashier)
     |                                |
     |                                └── 1:N ──── [Refund]
     |
     ├── 1:N ──── [Product] ──── N:1 ──── [Category]
     |
     ├── 1:N ──── [Inventory]
     |
     └── 1:N ──── [Order] (qua branch)
                     |
                     ├── N:1 ──── [User] (cashier)
                     ├── N:1 ──── [Customer]
                     └── 1:N ──── [OrderItem] ──── N:1 ──── [Product]

Quan hệ chính:
  • Store     → có nhiều Branch, nhiều Product, một User làm Admin
  • Branch    → có nhiều User (nhân viên), nhiều Order, nhiều ShiftReport
  • User      → thuộc Store và/hoặc Branch, có Role xác định quyền
  • Order     → có nhiều OrderItem, thuộc Branch, do Cashier tạo
  • ShiftReport → do Cashier tạo khi bắt đầu/kết thúc ca

VI. LUỒNG HOẠT ĐỘNG CHÍNH
================================================================================

------ A. Luồng Đăng ký / Đăng nhập ------
  1. POST /auth/signup  → Đăng ký tài khoản (không được đăng ký ROLE_ADMIN)
  2. POST /auth/login   → Đăng nhập, nhận JWT token
  3. Dùng JWT token trong header: Authorization: Bearer <token>
  4. JwtValidator filter kiểm tra token mỗi request

------ B. Luồng Quản lý Store ------
  1. Admin tạo Store: POST /api/stores
  2. Admin tạo Branch trong Store: POST /api/branches
  3. Admin tạo nhân viên cho Store: POST /api/employees/store/{storeId}
  4. Admin tạo nhân viên cho Branch: POST /api/employees/branch/{branchId}
     (Khi tạo ROLE_BRANCH_MANAGER phải truyền branchId)

------ C. Luồng Bán hàng (POS) ------
  1. Cashier đăng nhập, lấy JWT
  2. Cashier bắt đầu ca: POST /api/shifts/start
  3. Cashier tạo đơn hàng: POST /api/orders
     - Chọn sản phẩm (productId + quantity)
     - Hệ thống tự tính total = sellingPrice × quantity
     - Gắn cashier vào order tự động qua JWT
  4. Nếu có hoàn tiền: POST /api/refunds
  5. Cashier kết thúc ca: POST /api/shifts/end
     - Hệ thống tự tính: totalSales, totalRefunds, netSale
     - Thống kê theo phương thức thanh toán (CASH/CARD/UPI...)
     - Top 5 sản phẩm bán chạy
     - 5 đơn hàng gần nhất

------ D. Luồng Quản lý Kho ------
  1. Tạo sản phẩm: POST /api/products
  2. Thêm hàng vào kho: POST /api/inventory
  3. Xem tồn kho: GET /api/inventory

VIII. BẢO MẬT
================================================================================

1. JWT Authentication:
   - Token tạo bằng JJWT 0.12.6
   - Mỗi token chứa email + role của user
   - JwtValidator kiểm tra token trong header "Authorization: Bearer ..."
   - SecurityContextHolder lưu thông tin auth cho mỗi request

2. Password Encryption:
   - Mật khẩu mã hóa bằng BCryptPasswordEncoder
   - Không bao giờ lưu plain text

3. CORS:
   - Cho phép: http://localhost:5173 (Vite/React), http://localhost:3000
   - Headers, Methods: cho phép tất cả

4. Security Rules:
   - /auth/**, /swagger-ui/**, /v3/api-docs/** → PUBLIC (không cần JWT)
   - /api/** → Cần đăng nhập (authenticated)
   - Các endpoint còn lại → PUBLIC
